# Data Contract Specification

**Project:** `HOPIUM_sih26170`  
**Document:** `docs/DATA_CONTRACT.md`

---

## 1. Schema Definitions

Each row in a component burn-in dataset represents a single electronic component parameter measurement trajectory across burn-in timepoints.

### Required Fields

| Field Name | Type | Description | Allowed / Valid Range |
| :--- | :--- | :--- | :--- |
| `lot_id` | String | Unique manufacturing lot identifier | Non-empty string |
| `component_id` | String | Unique component identifier within lot | Non-empty string |
| `parameter_name` | String | Measured parameter identifier (e.g., `Iddq`, `leakage_current`, `propagation_delay`) | Allowed parameters list |
| `unit` | String | Unit of measurement (e.g., `uA`, `nA`, `ps`) | Non-empty string |
| `value_0h` | Float | Measurement at 0 hours (pre-burn-in) | Numeric (non-null) |
| `value_24h` | Float | Measurement at 24 hours | Numeric (non-null) |
| `value_96h` | Float | Measurement at 96 hours (historical reference / ground truth) | Numeric (nullable in screening) |
| `value_168h` | Float | Measurement at 168 hours (ground truth prediction target) | Numeric (nullable in screening) |
| `spec_min` | Float | Official datasheet minimum limit (if applicable) | Numeric or NaN |
| `spec_max` | Float | Official datasheet maximum limit (if applicable) | Numeric or NaN |

---

## 2. Parameter Scope

Initial parameters targeted for SIH26170 synthetic generation and modeling:
1. `Iddq` — Quiescent supply current ($\mu A$)
2. `leakage_current` — Input/Output leakage current ($nA$)
3. `propagation_delay` — Signal propagation delay ($ps$)

*Note: Additional component parameters may be integrated following the same trajectory schema.*

---

## 3. Data Integrity & Validation Rules

1. **Non-Negative Measurements:** Electrical parameters such as $I_{ddq}$ and leakage current must be non-negative unless physically defined otherwise.
2. **Timepoint Consistency:** Trajectory readings must follow temporal ordering `0h -> 24h -> 96h -> 168h`.
3. **No Duplicate Identity:** The combination of `(lot_id, component_id, parameter_name)` must be unique per dataset.

---

## 4. Synthetic Data Provenance Contract

All synthetic data files generated by the Phase 1 Synthetic Data Engine must strictly contain metadata header information:
- `is_synthetic: true`
- `generator_version`: String ID of generator version.
- `random_seed`: Integer seed used for reproducibility.
- `disclaimer`: `"SYNTHETIC DATASET GENERATED FOR SIH26170 EXPERIMENTATION. NOT REAL ISRO/INDUSTRY DATA."`
